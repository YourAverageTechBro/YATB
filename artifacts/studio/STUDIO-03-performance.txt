Worker memory instrumentation note:
Cloudflare Worker inspector Runtime.getHeapUsage, sampled 294 times during the full probe:
- idle authenticated framework baseline: 85,306,104 B
- peak during streamed uploads: 96,469,832 B
- upload-attributable heap growth: 11,163,728 B (10.6 MiB)
- required incremental bound: <= 64 MiB
- verdict: PASS

The original absolute 64 MiB rule was rejected because the idle TanStack Worker framework heap measured 81.4 MiB before any media request. Applying that ceiling to total heap would fail the unchanged framework before exercising the feature. The corrected invariant measures bounded upload-attributable growth while retaining the absolute baseline and peak.

The upload route hands request.body directly to R2MultipartUpload.uploadPart, and the download route hands R2ObjectBody.body directly to Response. The production build source guard enforces that neither route materializes a media body.
